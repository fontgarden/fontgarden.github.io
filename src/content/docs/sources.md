## The layout

```
├── AGENTS.md
├── AUTHORS.txt
├── CONTRIBUTORS.txt
├── OFL.txt
├── README.md
├── CONTEXT.md
├── STATUS.md
├── Makefile
├── requirements.in
├── requirements.txt
├── .agents
│   └── tasks
├── documentation
│   └── google-fonts.md
├── fonts
│   ├── ttf
│   └── variable
├── sources
│   ├── Style.designspace
│   ├── Style-Regular.ufo
│   ├── Style-Bold.ufo
│   ├── config.yaml
│   ├── held-out-glyphs.toml
│   └── specimen
```

The layout follows the Google Fonts project template, with the Font.Garden files added. The tools are not in the repository. They are in [fgtools](https://github.com/fontgarden/fgtools). A Python file in `sources/` holds only what one font needs.

## sources

| path | content |
| --- | --- |
| `Style-Master.ufo` | One UFO for each master. |
| `Style.designspace` | The masters, the axes and the named instances. A project with one master has no designspace. |
| `config.yaml` | The recipe of the gftools builder. A project is a directory that contains this file. |
| `held-out-glyphs.toml` | The cases of the drafting evaluation. |
| `proof-samples.toml` | Optional. Text samples for the web proof and for the proof view and the Proof section of Runebender. |
| `specimen/` | Optional. The specimen image and `labels.json`, for a font traced from a specimen. |

Only drawn `<source>` masters are training data. Instances are not. Generated files go to `output/`, which Git ignores.

Files that people edit use TOML with comments. JSON is only for data that a program writes. `config.yaml` is YAML because gftools requires it.

## CONTEXT.md

`CONTEXT.md` is the one design file of a project. It holds the numbered design rules of the style. Below a rule, a `toml` code block holds the values that the tools check for that rule:

````markdown
R1. Every point is on the 2-unit grid. Structural points are on the 8-unit grid.

```toml
[grid]
source = 2
machine_draft = 8
```
````

- Agents and people read the whole file. Runebender gives it to its agents.
- `fgtools` reads only the `toml` blocks, as one TOML document: the grid, the stroke targets, the weights, the mark colors, the reference fonts, the QA exclusions and the start date of the corrections list.
- A design value is stated only in this file.

## documentation

`documentation/google-fonts.md` is the one document of the release: the project facts, the QA, the package and, for a traced font, the origin of the specimen. The folder also holds the Google Fonts article. A project has no other documents: the design is in `CONTEXT.md`, and the way of work is in `AGENTS.md`.

## Agent files

`AGENTS.md` gives the rules for coding agents. `.agents/tasks/` holds task contracts for long and unattended tasks. Each contract gives a goal, acceptance checks, constraints and the form of the report.

## What does not belong

The repository holds sources, tests and maintained documents. It does not hold records of work.

- No worklogs, handoffs, receipts, reports, plans, audits or dated documents. The Git history is the record of work.
- A tracked file has at most 500 KB. A specimen scan in `sources/specimen/` can be larger.

`fgtools check-repository` enforces these rules, and `make test` runs it in CI. Each tracked file must have a place in the layout, which is the same for every Font.Garden project and is in fgtools. The command also fails when a document names a file or a `make` target that does not exist. A Python file in `sources/` is optional: it holds only what one font needs, for example its own Fontspector checks.

## Top-level files

- `README.md` states what the style is and gives the commands.
- `STATUS.md` is generated by `make status` from the mark colors.
- `OFL.txt`, `AUTHORS.txt`, `CONTRIBUTORS.txt`: see [Licenses](/docs/licenses/).
- `Makefile` is the entry point for every workflow. `make help` lists the targets. Each target calls `fgtools`.
- `requirements.txt` pins every Python dependency, with fgtools pinned to a commit.
